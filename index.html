Engineering approach

Make the signal visible

I work best when a complex system becomes legible: clear contracts, observable behavior, and evidence for every important decision.

  1. 01

    Frame the real constraint

    Separate the user problem from the first proposed solution.

  2. 02

    Build a measurable path

    Define inputs, outputs, failure modes, and evaluation before polishing.

  3. 03

    Test the seams

    Focus on state changes, boundaries, and the places where systems disagree.

  4. 04

    Communicate the result

    Leave behind a system and an explanation that another person can use.
